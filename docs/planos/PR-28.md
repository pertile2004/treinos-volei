## 2. Contrato
Nenhuma rota nova em /api/v1 e nenhuma rota existente muda de formato.

**GET /pulse** (rota web do pacote; caminho em `PULSE_PATH`, padrão `pulse`)
- Quem pode: só usuário autenticado (sessão Sanctum/cookie, guard web) com papel `admin`, em qualquer ambiente (o padrão do pacote, que libera o painel em `local`, foi substituído pelo gate `viewPulse` em `AppServiceProvider`).
- Resposta: 200 com o HTML do painel (Livewire; em inglês, uso interno do admin). Traz o header `X-Request-Id` como todas as respostas.
- Erros: 403 para visitante, jogador, treinador e usuário sem papel. 404 e 422 não se aplicam.
- Até o PR-04 a coluna `users.papel` não existe: o gate lê `getAttributes()['papel']` (enum `Papel` ou texto) e devolve falso quando não há papel.

**Linha de log por requisição** (canal `requisicoes`, config `logging.requisicoes`, env `LOG_REQUISICOES_CHANNEL`; padrão arquivo diário `storage/logs/requisicoes.log` em JSON; em produção `stderr`). Nível INFO, mensagem `requisicao`, e no `context` exatamente:
```json
{ "request_id": "3f6c1c1e-...", "metodo": "GET", "rota": "api/v1/treinos/{treino}", "status": 404, "duracao_ms": 2.83, "usuario_id": null }
```
- `rota` é o padrão da rota (nunca a URL com ids); `null` quando nenhuma rota casa (404 de URL inexistente). Sem corpo, query string, cookies ou e-mail.
- `duracao_ms` é float com duas casas, medido pelo middleware `RegistrarRequisicao` (global, entre `RequestId` e `CabecalhosSeguranca`, logo vale para /api/v1, /up e /pulse).
- O `request_id` repete em `extra.request_id` (Context do PR-01): é o mesmo do header de resposta e do JSON de erro, e o mesmo que o front mostra na tela.
- O canal é separado do `daily` porque o teste do PR-01 exige exatamente uma linha por log de erro no canal padrão; a correlação com laravel.log é pelo `request_id`.

Contrato de erro do PR-01, conferido e não alterado: `{ "message": "...", "request_id": "<id>" }` (422 também `errors`).
