# Plano — PR-01 · Esqueleto do backend

Branch: feature/pr-01-esqueleto-backend · Base: dc24fe1 · Pacote de trabalho único: **backend** (dono de todos os arquivos abaixo).

## Objetivo
API Laravel 13 (PHP 8.4) em backend/ com PostgreSQL, qualidade automatizada (Pest 4, Larastan 6, Pint, Scramble), observabilidade básica (request id, log JSON, erros JSON) e as rotas públicas /api/v1/saude e /api/v1/referencias. Sem autenticação e sem models de domínio.

## Contrato
Todas as respostas (inclusive erro, /up e 404) trazem o header `X-Request-Id` e os cabeçalhos de segurança.

### GET /api/v1/saude — público, sem parâmetros
- 200: `{ "data": { "status": "ok", "banco": "ok", "versao": "0.1.0", "horario": "2026-11-06T12:00:00+00:00" } }`
- 503 (banco inacessível): `{ "message": "Banco de dados indisponível.", "request_id": "<id>", "data": { "status": "indisponivel", "banco": "fora", "versao": "0.1.0", "horario": "..." } }`
- `versao` vem de `config('app.versao')` (env `APP_VERSAO`, padrão `0.1.0`); `horario` é `now()->toIso8601String()` em UTC.
- A checagem do banco é `DB::connection()->getPdo()` + `select 1`, atrás da interface `App\Contracts\VerificadorBanco` (método `disponivel(): bool`), para o teste trocar a implementação.

### GET /api/v1/referencias — público, sem parâmetros
- 200: `{ "data": { "papeis": [...], "fundamentos": [...], "niveis": [...], "etapas": [...], "visibilidades": [...], "origens_sessao": [...] } }`; cada item é `{ "valor": "recepcao", "rotulo": "Recepção" }`, na ordem dos cases.
- Enums (string backed, em app/Enums, cada um com `rotulo(): string`):

| Enum | valor → rótulo |
|------|----------------|
| Papel | jogador → Jogador · treinador → Treinador · admin → Administrador |
| Fundamento | recepcao → Recepção · levantamento → Levantamento · ataque → Ataque · saque → Saque · bloqueio → Bloqueio · defesa → Defesa · preparo_fisico → Preparo físico |
| Nivel | iniciante → Iniciante · intermediario → Intermediário · avancado → Avançado |
| Etapa | aquecimento → Aquecimento · tecnica → Técnica · especifico → Específico · volta_a_calma → Volta à calma |
| Visibilidade | privado → Privado · atletas → Atletas · publico → Público |
| OrigemSessao | cronometro → Cronômetro · registro_rapido → Registro rápido |

### Request id
- Middleware global `App\Http\Middleware\RequestId`: usa o `X-Request-Id` recebido se casar com `^[A-Za-z0-9._-]{8,64}$`; senão gera `Str::uuid()`. Faz `Context::add('request_id', $id)` e devolve o header na resposta.

### Erros em /api/*
- Sempre JSON: `{ "message": "...", "request_id": "<id>" }`; em 422 também `errors`. Fora de `local` (APP_DEBUG=false) nunca há `exception`, `file`, `line` nem `trace`.
- Mensagens: 404 "Recurso não encontrado." · 401 "Não autenticado." · 403 "Ação não autorizada." · 405 "Método não permitido." · 422 mensagem do validador · 429 "Muitas tentativas. Tente de novo em instantes." · 500 "Erro interno do servidor." · 503 "Serviço indisponível."
- Implementação em `bootstrap/app.php` (`withExceptions`: `shouldRenderJsonWhen` para `api/*` + `render`/`respond` acrescentando `request_id`).

### Cabeçalhos de segurança (middleware global `CabecalhosSeguranca`)
`X-Content-Type-Options: nosniff` · `X-Frame-Options: DENY` · `Referrer-Policy: strict-origin-when-cross-origin` · `Permissions-Policy: camera=(), microphone=(), geolocation=()` · `Strict-Transport-Security: max-age=31536000; includeSubDomains` só em produção.

### Outras rotas
GET /up (padrão do Laravel, 200) · GET /docs/api (Scramble, só em `local`, comportamento padrão do pacote) · GET /sanctum/csrf-cookie (vem do Sanctum).

## Riscos e limites do ambiente
- Sem Docker nesta máquina: `npm run dev` e o docker-compose.yml não são exercitados aqui; conferir a API com `artisan serve --port=8001` contra o PostgreSQL local e registrar a pendência em ESTADO.md.
- PHP local sem pcov: testes sem cobertura aqui; a cobertura roda só no CI.
- O job `backend` só é validado no GitHub; avisar o dono do repositório para torná-lo obrigatório (pendência).
- boost:install pode exigir interação (ver acima). A tag do mailpit e a action setup-php precisam ser confirmadas por quem implementa, sem inventar versão.
- Os valores de Nivel (iniciante, intermediario, avancado) não estão na especificação: opção mais simples, registrar em ESTADO > Pendências e no ADR.
- Conflito provável com o PR-02 em package.json, ci.yml, README, CHANGELOG, ESTADO e ROADMAP: resolver com `git merge origin/main`.
- Banco de teste desta cópia: volleypro_pr01 (variável DB_DATABASE); nunca usar migrate:fresh pelo terminal.
