# Plano — PR-21 · Agenda e lembretes no app

Branch: `feature/pr-21-agenda` (base: construcao/base + sementes `fd5eb59` tabela/model/factory de agendamentos e `8fe72fb` acesso à API de treinos no front). Pacotes de trabalho: **backend**, **frontend**, fechamento pelo tech lead.

## 1. Objetivo
RF-13: agendar treino por dia e hora, listar por semana, ver concluídos, editar e remover; vincular automaticamente a sessão ao agendamento de hoje; "Agenda do dia" para o Início; aviso discreto de treino de hoje pendente. Fecha a RN-08 (excluir treino remove os agendamentos futuros dele).

Contexto da frente: nesta branch não existem login no front (PR-05), POST /sessoes (PR-16) nem DELETE /treinos/{id} (PR-15). O backend é protegido por `auth:sanctum` + Policy; o vínculo automático e a RN-08 ficam como métodos públicos do `AgendamentoService`, testados direto, para os services daqueles cards chamarem no fechamento das suas frentes.

## 2. Contrato (/api/v1, sessão Sanctum) — detalhado em docs/API.md > PR-21
Recurso `Agendamento`:
```json
{ "data": { "id": 12, "data": "2026-11-09", "hora": "18:30", "concluido": false, "sessao_id": null,
            "treino": { "id": 5, "nome": "Saque e recepção", "duracao_estimada_minutos": 40 } } }
```
`hora` "HH:MM" ou null; `concluido` = `sessao_id` não nulo; `treino` por eager loading com `withTrashed`. O envelope `data` é montado à mão no Resource (o recurso tem um campo `data`); o 201 vem de `wasRecentlyCreated`.

| Rota | Entrada | Sucesso | Erros |
|---|---|---|---|
| GET /agendamentos | `de`, `ate` (Y-m-d, obrigatórios, `ate >= de`, até 31 dias corridos contando os extremos) | 200 `{ data: [...] }` do dono, por data, hora (nulos por último) e id; sem paginação | 401; 422 em `de`/`ate` |
| POST /agendamentos | `treino_id` (int, treino não excluído e visível pela RN-06), `data` (Y-m-d, hoje ou futuro em America/Sao_Paulo), `hora` (null ou H:i) | 201 | 401; 422 (`treino_id` "Escolha um treino." sem revelar se existe; `data` "Informe a data." / "A data não pode ser anterior a hoje."; `hora` formato H:i) |
| PATCH /agendamentos/{id} | `data` e `hora` opcionais, mesmas regras; `treino_id`/`sessao_id` ignorados | 200 | 401; 404 (não existe ou é de outro); 422 concluído: `errors.agendamento` "Este agendamento já foi concluído." |
| DELETE /agendamentos/{id} | — | 204; a sessão vinculada continua | 401; 404 |

Rate limit 60/min citado no rascunho: não configurado aqui (o throttle do grupo `api` é transversal; fica para o card de autenticação).

### Serviços para os outros cards
- `AgendamentoService::vincularSessaoDeHoje(Sessao): ?Agendamento` — só sessão com `treino_id`, criada agora; pega o agendamento pendente de hoje do mesmo usuário e treino (menor hora, depois menor id); uma sessão que já concluiu um agendamento nunca conclui outro. A chamar em `SessaoService::registrar` (PR-16) dentro da transação, fora do reenvio idempotente.
- `AgendamentoService::removerFuturosDoTreino(Treino): int` — RN-08: apaga os pendentes do treino com `data >= hoje`, de todos os usuários. A chamar no service de exclusão de treino (PR-15) dentro da transação.

## 3. Modelo (semente fd5eb59; docs/MODELO-DE-DADOS.md)
`agendamentos`: id · usuario_id → users (cascata) · treino_id → treinos (cascata, índice) · data date (dia local) · hora time null · sessao_id → sessoes null, `nullOnDelete` (índice) · timestamps. Índice (usuario_id, data). Sem deleted_at. Model `Agendamento` com `#[Table]`, `#[Fillable(['treino_id','data','hora'])]`, cast `data: date`, relações `usuario`, `treino()->withTrashed()` e `sessao`. `usuario_id` e `sessao_id` fora do fillable: criar por `$usuario->agendamentos()->create()` e vincular por `associate()`.

## 4. Regras garantidas no servidor
- RN-01: `hoje()` = `now('America/Sao_Paulo')->toDateString()` em validação, vínculo e RN-08; a semana (segunda a domingo) é calculada no front e enviada em `de`/`ate`.
- RN-06: `treinoDisponivel()` aceita treino do usuário, público, ou com visibilidade atletas cujo autor é o `treinador_id` do usuário (subconsulta, uma query só).
- RN-11: `AgendamentoPolicy` (`update`/`delete` do dono; alheio = `denyAsNotFound` → 404); a listagem filtra por `usuario_id`.
- RN-13: nada de "concluir à mão": o item pendente oferece "Iniciar treino" (/treinar/:treinoId); concluir acontece pelo vínculo da sessão.

## 8. Decisões simples (registradas em ESTADO > Pendências)
"Futuros" da RN-08 = hoje em diante e pendentes · data passada não se agenda · concluído não se edita (só pelo vínculo) · listagem por intervalo sem paginação · mesmo treino pode ser agendado mais de uma vez no dia · sessão sincronizada offline no dia seguinte não acha o agendamento de "hoje".
