## 2. Contrato

### GET /api/v1/estatisticas — logado (`auth:sanctum`)
Sempre os dados do próprio usuário; não há parâmetro de usuário (o do atleta é o PR-24).

Entrada (query string), validada em `EstatisticasRequest`:
- `periodo`: obrigatório, `in:semana,mes,3meses,ano` (valores do enum `PeriodoEstatistica`). Mensagem única para ausente ou inválido: "Informe um período válido: semana, mes, 3meses ou ano."

Janelas (calculadas com Carbon em `config('volleypro.fuso')` = America/Sao_Paulo, semana começando na segunda; `fim` inclusivo):

| periodo | janela | granularidade | pontos |
|---------|--------|---------------|--------|
| semana | segunda a domingo da semana atual | dia | 7 |
| mes | semana atual + 3 anteriores | semana | 4 |
| 3meses | semana atual + 12 anteriores | semana | 13 |
| ano | mês atual + 11 anteriores | mes | 12 |

Resposta 200 (exemplo com "agora" = sexta 06/11/2026, periodo=semana):
```json
{ "data": {
  "periodo": "semana", "fuso": "America/Sao_Paulo", "inicio": "2026-11-02", "fim": "2026-11-08",
  "volume": { "granularidade": "dia", "total_minutos": 105, "pontos": [
    { "inicio": "2026-11-02", "minutos": 45 }, { "inicio": "2026-11-03", "minutos": 0 }, { "inicio": "2026-11-04", "minutos": 60 },
    { "inicio": "2026-11-05", "minutos": 0 }, { "inicio": "2026-11-06", "minutos": 0 }, { "inicio": "2026-11-07", "minutos": 0 }, { "inicio": "2026-11-08", "minutos": 0 } ] },
  "desempenho": [
    { "fundamento": "recepcao", "acertos": 42, "erros": 18, "tentativas": 60, "percentual": 70.0 },
    { "fundamento": "levantamento", "acertos": 0, "erros": 0, "tentativas": 0, "percentual": null },
    { "fundamento": "ataque", "acertos": 0, "erros": 0, "tentativas": 0, "percentual": null },
    { "fundamento": "saque", "acertos": 15, "erros": 5, "tentativas": 20, "percentual": 75.0 },
    { "fundamento": "bloqueio", "acertos": 0, "erros": 0, "tentativas": 0, "percentual": null },
    { "fundamento": "defesa", "acertos": 0, "erros": 0, "tentativas": 0, "percentual": null },
    { "fundamento": "preparo_fisico", "acertos": 0, "erros": 0, "tentativas": 0, "percentual": null } ],
  "frequencia": { "semana_inicio": "2026-11-02", "semana_fim": "2026-11-08", "dias_treinados": 2, "meta": 3, "datas": ["2026-11-02", "2026-11-04"] }
} }
```
Regras do formato:
- `inicio`, `fim` e `pontos[].inicio` são datas locais (AAAA-MM-DD, fuso SP): primeiro dia do balde (dia; segunda da semana; dia 1 do mês).
- `pontos` vem sempre completo e em ordem crescente; balde sem sessão tem `minutos: 0` (zero de volume é dado real). `minutos = round(segundos / 60)` por balde; `total_minutos` é a soma dos baldes.
- `desempenho` traz todos os fundamentos do enum `Fundamento`, na ordem do enum. `percentual` é número com 1 casa (`70.0`, `0.0`; `JSON_PRESERVE_ZERO_FRACTION` no Resource) ou `null` quando `tentativas = 0`. Nunca 0 no lugar de null (RN-02).
- `frequencia` é sempre da semana atual, qualquer que seja o `periodo` (RN-04). `meta` = users.meta_semanal. `datas` são os dias locais distintos com sessão (para o PR-20 marcar S T Q Q S S D).
- Rótulos dos fundamentos vêm de GET /referencias, não desta rota.

Erros: 401 não autenticado · 422 `periodo` ausente ou inválido (`errors.periodo`). 403, 404 e 429 não se aplicam (não há recurso de terceiro nem throttle no grupo).

## 3. Modelo e migrations
Nenhuma tabela, coluna ou índice novo deste card. Usa `sessoes` (usuario_id, iniciada_em timestamptz em UTC, duracao_segundos; índice (usuario_id, iniciada_em)), `sessao_series` (sessao_id, fundamento, acertos, erros) e `users.meta_semanal`. As migrations dessas tabelas chegam à main junto com este PR (commits-semente dos cards 04, 08, 12 e 16): o docs/MODELO-DE-DADOS.md registra as decisões tomadas onde o modelo era omisso.

## 4. Consultas agregadas (`EstatisticasService`)
Limites da janela calculados em PHP (Carbon no fuso SP) e convertidos para UTC; o WHERE usa `iniciada_em >= :ini_utc AND iniciada_em < :fim_utc` (fim exclusivo), aproveitando o índice. O fuso só entra no agrupamento (`AT TIME ZONE`). Exatamente três consultas por requisição, com o Query Builder (nenhum model carregado em laço):
1. Volume: `date_trunc(:unidade, iniciada_em AT TIME ZONE :fuso)::date` + `SUM(duracao_segundos)` agrupado; `:unidade` (day, week ou month) vem de um mapa fixo no service. Baldes vazios preenchidos em PHP.
2. Desempenho: `sessao_series JOIN sessoes`, `SUM(acertos)`, `SUM(erros)` por fundamento; em PHP percorre `Fundamento::cases()`.
3. Frequência: `DISTINCT (iniciada_em AT TIME ZONE :fuso)::date` na semana atual.

Sessão que cruza a meia-noite conta no dia em que começou (`iniciada_em`).

## 5. Regras de negócio
- RN-01: Carbon em America/Sao_Paulo, semana na segunda; dados em UTC; teste de virada (domingo 23:50 SP não entra na semana que começa à 00:10 de segunda) e de fuso (02:30 UTC de segunda cai no domingo local).
- RN-02: percentual null sem tentativas; `0.0` só com erros (zero real).
- RN-03: mapa fixo período → granularidade; soma de duracao_segundos em minutos.
- RN-04: dias distintos (data local) na semana atual contra users.meta_semanal.
- Isolamento: toda consulta filtra pelo id do usuário autenticado.

## 6. DemoSeeder (`backend/database/seeders/DemoSeeder.php`)
- Só roda em `config('volleypro.demo.ambientes')` = local, demo e testing (ambiente "demo" = APP_ENV=demo); fora deles lança RuntimeException. Senha das contas em `DEMO_SENHA` (`config('volleypro.demo.senha')`) e a do admin em `DEMO_SENHA_ADMIN` (`senha_admin`, obrigatória e diferente); sem elas, aborta. `.env.example` traz valor falso e o phpunit.xml fixa `senha-demo-de-teste`. Não é chamado pelo DatabaseSeeder.
- Idempotente: usuários por e-mail (`updateOrCreate`), exercícios e treinos por nome (`firstOrNew`); as sessões do Guto são apagadas e recriadas a cada execução.
- Contas (constantes públicas do seeder): guto@example.com (jogador, meta 3), admin@example.com (admin), carla@example.com (treinadora, codigo_convite CARLA234), pedro@example.com e ana@example.com (atletas da Carla).
- Como a biblioteca do PR-08 não existe nesta branch, o seeder cria 7 exercícios do admin (um por fundamento, sem vídeo) e 4 treinos públicos do admin; o Guto tem 2 treinos privados usados nas sessões de cronômetro. Registro rápido grava série por fundamento sem exercício.
- Guto: 13 semanas (semana atual + 12), plano determinístico por semana: seg 07:00 (cronômetro, recepção e saque), qua 19:30 (cronômetro, ataque e bloqueio), sex 21:30 (registro rápido, defesa; em UTC já é sábado), sáb 10:00 (cronômetro, recepção e saque). Faltas fixas: semana 5 sem segunda; semanas 2, 6 e 10 sem quarta; semana 9 sem sexta; semanas 1, 4, 7 e 10 sem sábado. Semanas mais antigas têm `intdiv(semana, 3)` acertos a menos por série. Só gera sessões com `iniciada_em < agora`. A tabela da semana de referência está em docs/historico/PR-19.md.

## 9. Tela (/evolucao)
- Título "Evolução" (o teste existente de rotas exige esse heading; o item da navegação também). Abas Semana, Mês, 3 Meses e Ano (componente Abas, teclado).
- Linha "Período de dd/mm/aaaa a dd/mm/aaaa". Botão "Ver como tabela" / "Ver gráficos" (44 px, `aria-pressed`).
- Cartão "Volume de treino (min)": linha Recharts com desenho `aria-hidden`; o conteúdo acessível é o resumo em texto ("Total no período… Maior volume em…") e a tabela equivalente. Cores só por variáveis CSS dos tokens.
- Cartão "Performance por fundamento": BarraDeProgresso por fundamento com percentual de 1 casa (formatarPercentual) ou "Sem dados" (texto, nunca 0%).
- Cartão "Frequência": "N de M dias nesta semana" + BarraDeProgresso.
- Tabelas com caption e th scope: volume (Período, Minutos) e performance (Fundamento, Acertos, Erros, % de acerto).
- Carregando: componente Carregando ("Carregando sua evolução…", role status). Erro: MensagemDeErro "Não foi possível carregar sua evolução. Tente novamente." com request id e botão "Tentar de novo". 401: alerta "Você precisa entrar para ver sua evolução." com link "Entrar". Vazio (total 0 e sem tentativas): EstadoVazio "Você ainda não tem treinos neste período." com botão-link "Registrar um treino" para /treino.
