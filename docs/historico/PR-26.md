# PR-26 — PWA instalável
Integrante 3 · 2026-11-06 · Branch `feature/pr-26-pwa` · Base: main após o PR-03 (8b7f2f8). Só frontend.

## O que foi feito
- vite-plugin-pwa 2.0.0 em frontend/vite.config.js: manifest em pt-BR ("VOLLEY PRO", tema e fundo #0E0E0E, standalone, ícones 192/512 any e maskable), pré-cache do app shell, fallback de navegação para o index.html com exclusão de /api, /sanctum, /docs, /up e /pulse, e stale-while-revalidate só para GET de /api/v1/exercicios e /api/v1/treinos (lista e detalhe), cache `api-biblioteca`, só respostas 200, até 200 entradas por 7 dias. /eu, /sessoes e o resto da API nunca entram em cache.
- Ícones em frontend/public/icones/ (SVG, PNG 192/512 any e maskable, apple-touch-icon) gerados por frontend/scripts/gerar-icones.mjs, só com Node, a partir dos tokens do DESIGN.md.
- index.html com description, theme-color, ícone SVG e apple-touch-icon.
- src/lib/pwa.js: `limparCachesDoApp()` (apaga os caches `api-*`, preserva o app shell) e `encerrarSessaoLocal(queryClient)`. O http.js chama a limpeza em todo 401.
- AvisoNovaVersao (design system, 15º componente, no catálogo /dev/componentes) e src/app/AtualizacaoDoApp.jsx (registra o service worker por `virtual:pwa-register/react` e mostra o aviso; "Atualizar" ativa o service worker novo e recarrega), montado em main.jsx.
- Testes: 4 arquivos Vitest novos e 3 casos no http.test.js (23 testes novos); suíte com 30 arquivos e 331 testes passando. Spec Playwright frontend/e2e/pwa.spec.js escrito, não executado (sem infra do Playwright nesta branch).

## Decisões tomadas
- ADR-026: vite-plugin-pwa 2.0.0 (peer vite ^8 confirmado), atualização por aviso (`registerType: 'prompt'`), o que é e o que não é cacheado, e as duas camadas de cache (TanStack Query em memória e Cache Storage em disco).
- Seguiu-se o card do ROADMAP (stale-while-revalidate de exercícios e treinos) e não a nota "cache só do shell": sem essa rota o aceite "sem rede mostra a biblioteca já vista" não existe. Para voltar a só shell, basta remover o bloco `runtimeCaching` do vite.config.js.
- Limpeza dos caches em qualquer 401 (também já em /entrar), não só no ramo que redireciona.
- O módulo de auth (PR-05) não existe nesta branch: em vez de editar o "sair", `encerrarSessaoLocal(queryClient)` fica exportada para o PR-05 chamar no sucesso de sair e no DELETE /eu.
- AvisoNovaVersao fixo no topo (não embaixo), para nunca cobrir a NavInferior nem o botão principal do treino; montado em main.jsx, não no AppShell, para aparecer também nas páginas públicas.
- Nos testes, `virtual:pwa-register/react` é apontado por `test.alias` para src/testes/pwa-registro-desligado.js (o runner do Vitest no Windows não carrega o id virtual do plugin); em dev e build vale o módulo real. Por isso AtualizacaoDoApp.registro.test.jsx prova que o app monta com o substituto; o comportamento do módulo virtual real só é conferido no build + preview. O Vitest exclui e2e/**.
- Sem arte do Figma: ícone gerado por script (bola verde-limão sobre o fundo), sem dependência nova.

## Como testar
1. `npm run verificar` (backend e frontend; o build precisa mostrar "PWA v2.0.0 mode generateSW precache 18 entries" e gerar dist/sw.js, dist/workbox-*.js e dist/manifest.webmanifest).
2. `npm --prefix frontend run build` e `npm --prefix frontend run preview`; em http://localhost:4173: /manifest.webmanifest responde 200 `application/manifest+json`, /sw.js 200, /icones/icone-512.png 200 `image/png`; o HTML tem `<link rel="manifest">`.
3. No Chrome ou Edge, abrir a prévia > DevTools > Application > Manifest: sem erros de instalabilidade e com a opção de instalar na barra de endereço. Para ver o aviso de nova versão: com a prévia aberta, rodar o build de novo e recarregar; "Nova versão disponível." aparece no topo; "Atualizar" recarrega com a versão nova.

Nesta máquina (sem navegador real): aceite de instalação e troca de versão não conferidos; conferidos o build, o conteúdo do sw.js (NavigationRoute com denylist e StaleWhileRevalidate com statuses [200]) e as respostas do `vite preview`, inclusive o proxy de /api e /sanctum continuando a encaminhar para a API (502 com a API desligada, não o index.html).

## O que o próximo integrante precisa saber
- PR-05 (auth), BLOQUEANTE (revisão do PR-26, RN-11): no sucesso de "sair" e no DELETE /eu, chamar `encerrarSessaoLocal(queryClient)` de src/lib/pwa.js e cobrir com teste (`caches.delete('api-biblioteca')` chamado); sem isso, a limpeza dos caches só acontece no 401. Ao criar o playwright.config.js, rodar frontend/e2e/pwa.spec.js contra o `vite preview` (não o dev) e ajustar o que o spec supõe das telas (heading h1 em /biblioteca, /sanctum/csrf-cookie 204).
- Em dev e nos testes não há service worker (devOptions desligado): o proxy /api, /sanctum e /docs não passa por ele. Para depurar o PWA, use build + preview.
- Duas camadas de cache: o TanStack Query (memória) responde primeiro dentro da aba; o service worker (disco) responde quando a aba é nova ou está offline. Um dado "velho" na tela pode vir de qualquer uma: DevTools > Application > Cache Storage mostra a do service worker.
- PR-30 (deploy no Laravel): sw.js e manifest.webmanifest precisam sair da raiz do site, sem cache HTTP longo no sw.js e sem cair no fallback do index.html.
- Versão presa no navegador durante a demonstração: DevTools > Application > Service Workers > "Update" ou "Unregister", ou clicar em "Atualizar" no aviso.
- `npm audit` padrão lista vulnerabilidades low/moderate transitivas do workbox-build (glob, minimatch, deepmerge); o CI (nível high) passa.
