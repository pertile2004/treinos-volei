# PR-02 — Esqueleto base do frontend
Responsável: Integrante 3 · Data: 2026-11-06

## O que foi feito
- frontend/ com Vite 8, React 19 (JavaScript), Tailwind 4 pelo @tailwindcss/vite, React Router 8 e TanStack Query 5.
- src/lib/http.js: axios com baseURL /api/v1, withCredentials e withXSRFToken; X-Request-Id novo a cada requisição; em 419 busca /sanctum/csrf-cookie e repete uma única vez; em 401 vai para /entrar?voltar=<rota pedida>.
- src/lib/erros.js: `descreverErro(erro)` devolve status, mensagem em pt-BR e o request_id.
- Rotas das 23 telas da especificação, cada página só com o título, mais a 404 e a /dev/status (só em desenvolvimento), que consulta /api/v1/saude.
- AppShell com o link "Pular para o conteúdo", a navegação principal (Início, Biblioteca, Treino e Evolução; fixa embaixo e em coluna lateral a partir de 1024 px) e o landmark main.
- Componentes de estado: Pagina, Carregando, MensagemDeErro (mostra o request_id) e EstadoVazio.
- Tokens provisórios do docs/DESIGN.md no `@theme` do Tailwind.
- ESLint (flat config) com react-hooks e jsx-a11y, Prettier e Vitest com Testing Library, jsdom e MSW: 6 arquivos, 57 testes.
- Raiz: concurrently e os scripts `dev`, `dev:web` e `teste:web`; package-lock.json da raiz.
- CI: job `frontend` (Node 24, `npm ci`, lint, testes com cobertura, build e `npm audit --audit-level=high`).

## Decisões tomadas
- ADR-016: versões exatas do frontend e o concurrently na raiz; @testing-library/dom entrou na lista aprovada; `overrides` para o eslint-plugin-jsx-a11y aceitar o eslint 10.
- ADR-017: E2E_API_PORT e E2E_WEB_PORT trocam as portas no vite.config.js; a /dev/status só existe em desenvolvimento.
- O título da aba é definido pelo componente Pagina com `document.title` ("<título> · VOLLEY PRO").
- A /dev/status aceita os campos de /api/v1/saude na raiz ou dentro de `data`, porque o PR-01 ainda não estava na main.
- React Hook Form, Zod, vitest-axe e Playwright não foram instalados: entram com o primeiro PR que usar.
- O job `frontend` não usa BASE_REF; no job `governanca` ela continua definida por etapa.
- Arquivo além do plano: src/testes/renderizar.jsx, auxiliar dos testes de rotas, AppShell e status.

## Como testar
1. `npm run setup`, `npm ci` e `npm --prefix frontend ci`
2. `npm run verificar` (ou, em frontend/, a sequência do CI: `npm run lint`, `npm run test:cobertura`, `npm run build` e `npm audit --audit-level=high`)
3. `npm run dev:web`, abrir http://localhost:5173, navegar pelos quatro itens e abrir /dev/status e um endereço que não existe

- O `npm run dev` completo e a /dev/status com a API real ainda não foram conferidos: dependem do PR-01 (pendências no docs/ESTADO.md).
