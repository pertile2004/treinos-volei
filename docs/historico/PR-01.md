# PR-01 — Esqueleto do backend
Responsável: Integrante 2 · Data: 2026-11-06

## O que foi feito
- API Laravel 13.40.0 (PHP 8.4) em backend/, com Sanctum, PostgreSQL e rotas em /api/v1.
- GET /api/v1/saude (status, banco, versao e horario; 503 quando o banco está fora) e GET /api/v1/referencias (valor e rótulo dos seis enums).
- Enums Papel, Fundamento, Nivel, Etapa, Visibilidade e OrigemSessao, todos com `rotulo()` em pt-BR.
- Middleware RequestId (lê ou gera o X-Request-Id, grava em Context e devolve no header) e middleware CabecalhosSeguranca.
- Erros de /api/* em JSON padrão (message, request_id e, em 422, errors), sem detalhes internos com APP_DEBUG=false.
- Logs em JSON nos canais `daily` (desenvolvimento) e `stderr` (produção), com o request id em `extra`.
- `Model::shouldBeStrict()` fora de produção e mensagens de validação em pt_BR (backend/lang/pt_BR).
- Qualidade: Pest 4, Larastan nível 6, Pint e Scramble (/docs/api só em local); scripts do Composer `test`, `lint`, `analise` e `formatar`.
- Laravel Boost instalado em backend/ e registrado no .mcp.json da raiz.
- Raiz: docker-compose.yml (postgres:17 com os bancos volleypro e volleypro_teste, e Mailpit), scripts/dev.mjs (`npm run dev`), `npm run teste:api` e o job `backend` no CI.

## Decisões tomadas
- ADR-016: versões exatas das dependências, laravel/tinker na lista aprovada, imagens do Docker e tradução à mão.
- ADR-017: Laravel Boost só para o Claude Code e Scramble com a configuração padrão.
- ADR-018: interface VerificadorBanco na checagem de saúde.
- ADR-019: valores do enum Nivel (a confirmar com o grupo).
- O `install:api` não foi rodado de novo: o esqueleto já trazia o Sanctum, o config/sanctum.php, a migration e o routes/api.php. A rota /user gerada por ele saiu (autenticação é dos PRs 04 e 05).
- O config/cors.php foi removido: era igual ao padrão do framework e CORS está fora do escopo.
- Os arquivos de frontend do esqueleto (package.json, vite.config.js, resources/js e resources/css) e a view de boas-vindas foram removidos; routes/web.php ficou vazio.
- O trait App\Enums\Concerns\ComOpcoes monta a lista valor/rótulo de cada enum em um só lugar.
- Mailpit na v1.32.0 em vez da v1.33.0, que tinha poucos dias de publicada.
- No phpunit.xml o banco de teste é volleypro_teste, sem `force`: se a variável de ambiente DB_DATABASE existir, ela vale (é assim que o CI e as cópias de trabalho escolhem o banco).

## Como testar
1. `composer --working-dir=backend install`, copie backend/.env.example para backend/.env e rode `php backend/artisan key:generate`.
2. `npm run dev` (com Docker) ou, com PostgreSQL local, `php backend/artisan migrate` e `php backend/artisan serve`; abra /up, /api/v1/saude e /api/v1/referencias em http://127.0.0.1:8000.
3. `npm run verificar` (Pint, Larastan e 31 testes do Pest).

## O que o próximo integrante precisa saber
- O PHP precisa da extensão pdo_pgsql. Sem Docker, crie no PostgreSQL local o usuário `volleypro` e os bancos `volleypro` e `volleypro_teste` (passo a passo no README).
- O PR foi fechado em uma máquina sem Docker: o docker-compose.yml e o caminho completo do `npm run dev` ainda não foram exercitados. A API foi conferida com `php backend/artisan serve` contra um PostgreSQL local, inclusive o 503 com o banco inacessível.
- O PHP local não tinha pcov: a cobertura roda só no job `backend` do CI. Avise o dono do repositório para tornar esse job obrigatório.
- Rotas novas entram em backend/routes/api.php e já recebem o prefixo /api/v1. Não registre o prefixo de novo.
- Todo erro de /api/* passa pelo `respond` de backend/bootstrap/app.php, que troca a mensagem dos status 401, 403, 404, 405, 429, 500 e 503 pelas fixas em português. Para outros status, vale a mensagem da exceção.
- Enum novo: use o trait ComOpcoes, crie o `rotulo()` e acrescente a chave no ReferenciasService, no ReferenciasResource, no teste e no docs/API.md.
- O model User e as migrations padrão estão como vieram do Laravel; o PR-04 adapta o usuário ao modelo de dados com migration nova, sem editar as existentes.
- Antes de commitar, rode `composer --working-dir=backend formatar`: o CI barra o PR com `pint --test`.
- backend/CLAUDE.md e backend/.claude/skills vêm do Laravel Boost; as regras do projeto continuam no CLAUDE.md da raiz. O backend/AGENTS.md é o do esqueleto do Laravel (ver Pendências no ESTADO.md).
- Os testes escrevem no log diário de desenvolvimento (backend/storage/logs); as linhas com `"channel":"testing"` são deles.
