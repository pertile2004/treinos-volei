# PR-00 — Fundação do repositório
Responsável: Integrante 1 · Data: 2026-11-06

## O que foi feito
- Documentação do projeto em docs/: especificação, arquitetura, modelo de dados, contrato da API, design, roteiro de PRs, decisões, boas práticas, definição de pronto e integrantes.
- Regras de trabalho: CLAUDE.md, as skills /comecar e /encerrar e os agentes revisor e revisor-seguranca.
- Hooks do Claude Code em .claude/hooks/: resumo no início da sessão, guarda de comandos e formatador.
- Scripts da raiz (setup, verificar, verificar-docs e verificar-autoria) e os git hooks commit-msg e pre-push em .githooks/.
- CI de governança em .github/workflows/ci.yml: documentação viva, autoria e varredura de segredos.

## Decisões tomadas
- ADR-001 a ADR-014: decisões iniciais do projeto.
- ADR-015: ajustes no .claude/settings.json depois de conferir a documentação oficial (hooks em forma exec, regras de PowerShell, sessionUrl e onFailure).
- Os scripts não usam shell. No Windows, o npm e o Composer são chamados como `node npm-cli.js` e `php composer.phar` (scripts/lib/processos.mjs).
- As regras que detectam atribuição de IA ficam em um só lugar (scripts/lib/atribuicao.mjs) e servem ao CI e ao hook commit-msg.
- Além da lista da especificação, o guarda de comandos bloqueia `git -c user.name` ou `user.email`, `git pull --rebase`, `git checkout --force`, `git switch --discard-changes`, `git push --all` ou `--mirror` e `git push` sem destino quando a branch atual é a main.
- Actions do CI nas versões maiores atuais: actions/checkout v7, actions/setup-node v7 e gitleaks/gitleaks-action v3.

## Arquivos principais
- CLAUDE.md, .claude/settings.json, .claude/hooks/, .claude/skills/ e .claude/agents/
- scripts/ e .githooks/
- .github/workflows/ci.yml e .github/pull_request_template.md
- docs/

## Como testar
1. `npm run setup`
2. `node .claude/hooks/guarda-comandos.mjs --autoteste` e `node scripts/git/commit-msg.mjs --autoteste`
3. `npm run verificar -- --pronto`

## O que o próximo integrante precisa saber
- Antes de tudo, instale o Git for Windows, o Node 24 ou mais novo e o GitHub CLI, rode `gh auth login` e depois `npm run setup`.
- Na primeira sessão, aceite a confiança na pasta do projeto e confira /hooks e /permissions.
- O `npm run setup` acusa a falta do Docker; ele passa a ser necessário no PR-01.
- O guarda de comandos precisa do Node no PATH. Sem ele, todo comando de terminal do Claude Code fica bloqueado (falha segura).
- O Git e o GitHub CLI também precisam estar no PATH do Windows. Se o guarda bloquear o `git push` com "spawnSync git ENOENT", acrescente `C:\Program Files\Git\cmd` ao PATH e reinicie o VS Code.
- Os agentes revisores usam a ferramenta Bash, que no Windows depende do Git for Windows.
- No /encerrar, o `npm run verificar -- --pronto` do passo 2 só fica verde depois do commit do passo 3, porque o verificar-docs olha apenas o que já está commitado: faça o commit dos docs e rode a verificação de novo.
- No CI, a variável BASE_REF é definida por etapa, e não no job: a action do gitleaks também lê essa variável e falha se ela valer para o job inteiro. Mantenha assim ao criar os jobs backend, frontend e e2e.
- O gitleaks do CI é gratuito para repositório de conta pessoal. Se o repositório for de uma organização, ele exige a licença GITLEAKS_LICENSE.
